**3. Description (short):**
I built a CUDA batch image-processing tool that runs edge detection on 200
512x512 grayscale images in a single execution. Each image goes through three
GPU stages I wrote myself: a shared-memory-tiled 5x5 Gaussian blur (weights in
constant memory), a Sobel gradient-magnitude kernel, and histogram
equalization (shared-memory histogram with atomics, a parallel-scan kernel that
builds the lookup table on the GPU, and a LUT-apply kernel). To process many
images efficiently I used pinned host memory and multiple CUDA streams so
copies and kernels overlap; the CLI lets me choose the stream count, and I
compared 1 vs. 4 streams (results: <fill in from execution_log.txt>).

Challenges and lessons: handling halo/border pixels in the tiled blur without
out-of-bounds reads; reducing contention on global atomics in the histogram by
using per-block shared histograms; keeping the equalization LUT entirely on the
device so no synchronization with the host is needed per image; and learning
that overlap only helps once disk I/O and kernel time are balanced (the CPU-side
PGM read can become the bottleneck). Dataset: synthetic shape/gradient/noise
images generated by `scripts/generate_data.py` (USC-SIPI images can be used via
`scripts/convert_to_pgm.py`).
